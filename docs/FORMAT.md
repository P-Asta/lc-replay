# LCReplay schema 1

Version 0.23 retains schema 1. `TextureSnapshot.Linear` defaults to false and preserves linear data-map encoding in new captures. A room may have up to eight `AdditionalVolumes`, each with finite positive `Size` and finite `Center`; these are separate containment volumes, including the mine's special entrance region, not a combined enclosing box. Frames optionally include bounded `ParticleStyles` keyed by emitter ID; particle poses may refer to these IDs and add world velocity, 3D size/rotation, lifetime, remaining lifetime and random seed. Styles identify installed source effects and renderer state; `Simulate` marks observed active turret loops. Lines add optional material/shader identity, texture mode and alignment. Missing fields preserve the older read behavior, but cannot recover source effect identities absent from old recordings.

Playback decodes independent records using a bounded worker batch and yields them in file order. `ReplayFileIndex.ReuseWorldPayloads` is opt-in: returned world payloads and their children must be treated as read-only. The cache holds only weak references, checks the completed file's length/write timestamp, creates independent per-window record timestamps and revalidates reused payloads.

Each `.lcr` file starts with the eight ASCII bytes `LCREPL01`. Records follow without padding:

| Field | Encoding |
| --- | --- |
| Compressed payload length | Positive little-endian signed 32-bit integer |
| Expanded payload length | Positive little-endian signed 32-bit integer |
| Payload | One independent gzip member containing UTF-8 JSON |

The first payload is a `ReplayRecord` with `Kind: "header"`, `Time: 0`, and `Header.SchemaVersion: 1`. Other records have exactly one payload matching `Kind`: `frame`, `event`, or `world`. The writer closes a successful recording with `Kind: "end"`, which has no nested payload. JSON member names match the C# DTO properties. Quaternion order is X, Y, Z, W. Mesh vertex arrays contain consecutive X, Y, Z components; triangle arrays index vertices, not components. World and entity transforms use the recorder's coordinate conventions; bone poses are local to their parent. `EntitySnapshot.Renderers` contains optional `RenderPose` entries whose position, rotation and scale are relative to the entity root. Each renderer ID matches the corresponding `GeometrySnapshot.Id`; its `Active` flag captures visibility. Older schema-1 files without renderer poses load with an empty renderer list.

Version 0.20 retains schema 1. Audio `source-block` events add `global`: only genuinely global music/UI remains two-dimensional in playback; world sources use the spectator camera's position and the recorded distance settings. Sparse `visual` events store `renderer` visibility changes and `spray` HDRP decal projector poses/colors, keyed by capture-set ID. The `.lci` sidecar uses `LCIX0002` and marks visual records so bounded playback windows can carry prior visual state without reading older audio; an older sidecar is rebuilt from its `.lcr`. New recordings keep tombstones for destroyed moving renderers, and emission properties are prioritized in the existing bounded material snapshots.

Version 0.14 adds optional `ReplayFrame.SceneRenderers`: bounded world-space poses for generated furniture and doors without an entity owner. `GeometrySnapshot.IsMovingSceneRenderer` identifies these surfaces, and `Active` stores initial visibility. `GeometrySnapshot.RootBonePath` preserves the original skin root for animated enemy meshes. New audio `source-block` events include invariant-culture `x`, `y`, `z`, `spatial`, `min`, `max`, and `rolloff` fields; old events without these fields retain 2D mixed playback. All additions retain schema 1 and default to legacy behavior when absent.

Version 0.15 adds optional `ReplayFrame.Lines`: at most 128 world-space LineRenderer paths per frame, each with 2–32 finite points, end colors, widths and an indoor flag. Matching paths interpolate between frames; missing paths appear or disappear at sample boundaries. Older schema-1 recordings read this as an empty list. New recordings also tag entity-owned geometry with its dungeon room when it is spatially inside a generated tile.

Version 0.16 keeps schema 1. New `audio/source-block` events optionally include `player=true|false` to mark sources attached to a player or held item, and `capture=clip|tap` to identify readable-clip fallback for a virtualized source versus an audio callback. The header advertises `player-audio-origin` and `virtual-audio-readable-clips`. Older events lack these keys and continue playing; their player-origin sounds cannot be muted reliably. Each block still uses the bounded mono ADPCM format and source position/distance fields described below.

Version 0.3 adds optional embedded appearance fields without changing schema 1. `WorldSnapshot.Textures` contains unique IDs, dimensions and PNG bytes (base64 in JSON); `Materials` contains unique IDs, color, a texture ID, UV scale/offset and alpha cutoff. Geometry may contain UV pairs, normal triples, submesh index arrays, material IDs and skin data. Skin data contains entity-relative bone paths, 16 column-major matrix values per bind pose, and four bone indices/weights per vertex. Missing appearance arrays default to empty, preserving older files. No game asset paths or executable Unity objects are serialized.

Version 0.4 adds optional `GeometrySnapshot.MeshSourceId`, `IsInterior` and `RoomId` fields. A nonempty `MeshSourceId` refers to an **earlier static, non-proxy geometry entry in the same world**. An instance retains its own transform, visibility and material references but must have empty vertex, triangle, submesh, UV, normal and skin arrays. Missing, forward, self, cyclic, chained-instance and skinned-source references are rejected. This permits repeated room geometry to share one stored mesh without copying its vertex data into every instance. Empty defaults preserve older schema-1 files.

Version 0.5 adds optional `ReplayFrame.Anchors`, `GeometrySnapshot.AnchorId` and `WorldSnapshot.Lights` without changing schema 1. Anchor poses give moving environment roots a sampled world-space transform; a geometry/light anchor ID stores its pose relative to that root. The recorder currently uses the game's ship/elevator and ship animator roots. Light snapshots contain bounded type, transform, color, intensity, range and shadow settings. Older files load with empty anchor/light lists; playback uses the earlier unlit appearance for a world without recorded lights.

Version 0.6 adds optional `WorldSnapshot.CaptureSetId`, `Layer`, `Rooms` and `Environment`, plus material render queues, shader keywords and bounded property values. A capture set has separate exterior chunks and an interior record; playback merges records with the same capture-set ID before replacing the displayed world. `Rooms` store generated tile bounds used to decide whether the spectator is indoors. `Environment` stores blended HDRP sky, fog, exposure and color-grading parameters, with six bounded PNG cubemap faces when available. Playback creates a private HDRP volume and does not serialize Unity components or shaders. Empty capture-set IDs and missing environment/room data preserve older recordings.

Version 0.8 adds optional `GeometrySnapshot.Instances`, natural LOD metadata (`LodGroupId`, `LodLevel`, `LodCenter`, `LodSwitchDistance`) and `WorldSnapshot.ParticleEmitters` without changing schema 1. `Instances` is a flat array of at most 8,192 affine, finite, world-space 4×4 matrices for GPU-instanced meshes such as grass. Natural LOD entries carry a group ID and a near/far level selected by the spectator camera; unpaired entries fall back to their available level. Particle emitters store bounded looping-effect settings, not per-particle or GPU VFX state. Missing fields default to empty, preserving older recordings.

Version 0.9 adds optional `WorldSnapshot.LocalFogs` without changing schema 1. Each entry stores a bounded, active HDRP local volumetric fog volume's transform, color, density, size, face fades and distance fade. Texture and material masks are not embedded. Missing entries default to an empty list, so older recordings load but cannot recover local fog that was never captured.

Version 0.10 extends each optional local fog entry with mask mode, tiling, scrolling speed and a bounded raw RGBA 3D density mask when its source texture is CPU-readable. Each axis is limited to 64 voxels and the total mask budget is 4 MiB per world; missing masks default to empty. The reader validates exact RGBA byte count. Ground textures and distance-detail policies are playback decisions and do not change schema 1.

Version 0.11 keeps schema 1 but writes one physical `.lcr` per quota/deadline day. A new header marks `singleFile=true`. The file continues to contain independently compressed records until an `end` marker; no intermediate header or numbered file is inserted. A companion `.lci` stores record offsets and timestamps for fast opening; it can be rebuilt from the `.lcr`. Playback reads bounded virtual windows on demand with the preceding frame and latest world capture set. Older multipart files keep their existing reader and timeline. Ground color layers may now be captured at up to 2048 pixels per edge, with a 32 MiB PNG budget per world and 96 MiB expanded/48 MiB compressed per-record bounds. Unity Terrain without a MeshRenderer uses up to a 128×128 cell height field, sampled normals and UVs, plus an available terrain-layer texture.

Version 0.12 adds optional `WorldSnapshot.AssetScene`, `AssetGameVersion`, `AssetBuildIndex`, `AssetRendererPaths`, `AssetTerrainPaths`, `MapSeed`, `LevelId`, `DungeonSeed` and `DungeonFlow` fields without changing schema 1. A bounded component path is a sequence of transform sibling indices followed by component type and index. Paths refer only to renderers and Terrain components that were already present when the built-in moon scene loaded; procedural additions and moving objects retain embedded snapshots. Playback resolves those paths against an inert additive copy of the *same installed game version's* scene. Missing or mismatched moon assets cannot be recovered from the compact record and produce a playback error. Map/dungeon settings are recorded as provenance, not used to regenerate the dungeon. An environment-only exterior record may share a capture-set ID with earlier geometry records to update sky/fog after landing without duplicating the map.

Version 0.12.1 filters scene component paths before capture. Paths must be unique within their renderer or terrain kind and at most 256 characters; a world can reference at most 4,096 components. A surface that cannot be referenced uses the embedded-geometry capture path instead of invalidating the recording. The reader continues to reject malformed stored references.

Version 0.13 adds optional `LightSnapshot.UseColorTemperature` and `ColorTemperature` values (1,000–20,000 K), plus up to 256 `ReplayFrame.Particles` poses per frame. Particle poses contain finite world position, rotation, size, RGBA color and an indoor flag. Observed audio uses ordinary `event` records with `Category: "audio"`, `Name: "source-block"` and `rate`, `samples`, base64 `adpcm`, and `source` data. Each independent IMA-ADPCM block decodes to at most 8,192 mono samples at 22,050 Hz; the two-byte initial predictor is followed by packed four-bit deltas. The source value is a transient Unity instance ID, not a stable identity across runs. New optional fields default to empty or neutral values when reading older schema-1 files.

Static-batched renderers contribute only their own submesh range and compacted referenced vertices. Unowned static-batch slices use world-space vertices with an identity geometry transform, avoiding a second transform or shear approximation. Owned slices remain local to their recorded renderer pose. Distinct batch slices do not share mesh payloads merely because Unity stores them in the same combined buffer.

`IsInterior` and `RoomId` describe generated interior geometry. Playback shows exterior geometry when the spectator camera is outside, and hides it in recorded rooms while showing nearby interiors within a 105 m range. Visibility changes do not execute game occlusion scripts. The capture `WorldVertices` setting defaults to 500,000 unique vertices, accepts at most 1,000,000, and is distinct from the reader's per-geometry limit. Each capture record uses a conservative 45 MiB mesh estimate, leaving headroom in the 96 MiB expanded-record limit for textures and other world fields.

Default appearance limits are 256 textures, 2048 pixels per edge for reading, 32 MiB total PNG bytes per world, 8192 reader materials (1024 recorder materials) and 16 material slots per geometry. The recorder targets up to 2048-pixel ground color layers, 1024-pixel other natural/skinned primary maps, and lower resolution secondary maps, falling back by halves within a 5 MiB-per-image limit. The reader checks PNG IHDR dimensions before engine decoding, numeric array lengths and finite values, mesh/bone indices and resource references. Invalid image decoding at playback falls back to material color. Ground textures retain the captured base level at any distance; other textures use mipmaps with preserved alpha-test coverage in foliage. Resources are disposed with their world/viewer.

Frame and event nested timestamps must equal their record timestamp. Times are finite, nonnegative seconds since the current storage part began. Frames are complete snapshots and must have nondecreasing timestamps. Events and worlds can arrive out of timestamp order; the reader sorts them stably, retaining their recorded order at equal times. Entity IDs must be unique within a frame, geometry IDs within a world, and bone paths and renderer IDs within an entity. A missing entity disappears at the first frame that omits it. A newly present entity appears at that frame. Duplicate frame timestamps resolve to the final frame at that timestamp.

The writer creates a new file and refuses to overwrite an existing path. `TryWrite` transfers ownership of the record and its nested objects; callers must not mutate them after acceptance. Its bounded queue returns `false` without dropping an already accepted record when full, disposed, or failed. A recorder should stop and surface the condition. `CompleteAsync` drains accepted records, writes an end marker and closes the stream without waiting on the game frame; `Dispose` waits for that completion. Background serialization/I/O errors are exposed through `Error`, including after disposal, and omit the success end marker. An I/O failure can necessarily prevent already queued records from reaching disk.

The reader recovers the complete prefix when the final length prefix or compressed payload is physically truncated. A missing end marker produces a warning. Invalid complete records, unsupported schemas, invalid transforms, impossible mesh indices, and exceeded limits raise `InvalidDataException`; corruption is never silently treated as valid data. JSON type metadata is ignored, and the parser never instantiates arbitrary types from file contents. Each expanded size is bounded before decompression, and the actual expanded size must match its declaration.

The ordinary full-session reader retains a 1 GiB file/512 MiB aggregate limit, with 48 MiB compressed / 96 MiB expanded per record, 500,000 records, 432,000 frames, 1,000,000 total entity snapshots, 4,096 entities per frame, 512 bones and 512 renderer poses per entity, 100,000 events, 256 worlds, and seven days of elapsed time. `ReplayReadLimits` exposes these limits. New single-file playback uses a separate bounded index (16 GiB physical, 24 GiB expanded, 2,000,000 records and 1,000,000 frames) and loads approximately 180 MiB of frame/event data plus the latest world set per virtual window, under the ordinary 512 MiB in-memory window limit.

`ReplayTimeline.Sample` binary-searches the surrounding frames, linearly interpolates position and scale, and spherically interpolates rotation along the shortest quaternion arc. It preserves the left frame's discrete state until the next timestamp. It does not interpolate across a missing entity, kind change, or activation change. Matching active renderer poses interpolate their local transforms, allowing a stationary door entity's panel to rotate or slide. Renderer visibility and presence change at frame boundaries. The returned snapshot is independent of the loaded data. Queries outside the frame range clamp to the first or final pose.

## Whole-recording time and duration indexing

`ReplayRecordingTimeline` assigns each ordered part a global offset. With valid start timestamps, an offset is the later of its recorded start relative to the first part and the preceding part's end. Missing/earlier timestamps concatenate after the preceding part. This preserves capture gaps without overlapping the playback clock. `Locate` selects the part at a global timestamp; `LocalTime` clamps to that part's available duration, holding its final pose during a gap. Exact boundaries select the new part, and zero-duration parts do not trap seeking. The timeline accepts up to 10,000 distinct paths and seven days total.

`ReplayReader.ReadDuration` first validates the bounded header, then walks record lengths without decoding frame or texture payloads. A valid final end record supplies the completed duration. Incomplete files fall back to the bounded prefix-recovery reader. Invalid lengths and aggregate limits are rejected, and cancellation is observed during reads. This index operation does not substitute for full payload validation when a part is actually loaded.

Legacy playback keeps one active decoded part and at most one prefetched part. New single-file playback uses the same viewer with in-memory windows that share one disk path. Global UI time is converted to local window time for state/event lookup; displayed event timestamps include the window's global offset. The format remains schema 1, and the quota/day file layout is described separately in [ARCHIVE.md](ARCHIVE.md).
